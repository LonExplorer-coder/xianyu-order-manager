# 用唯一发货组档案持续组织同一轮发货记录

开放的合并发货组是随订单当前值和剩余待发数量动态计算的工作清单，不能直接充当发货后的稳定身份。系统在一个开放组第一次确认实际发出时建立唯一的发货组档案，并固定记录本轮成员订单身份；之后同一轮分批发货产生的多条发货记录都关联该档案。剩余待发数量归零后，档案从开放转为已完成，但档案、发货记录、包裹、订单商品和数量的层级继续保留。

发货匹配键只用于保守地形成开放组，不是档案身份。相同手机号和地址以后出现的新订单不属于既有档案成员：界面把它作为独立待发内容展示，第一次实际发出时建立新的档案；即使旧档案因撤销未交寄包裹重新开放，两轮也仍按各自成员订单和数量分别处理。这样既保留了用户熟悉的按收货信息成组方式，也避免把同一买家的不同发货轮次误认为一轮。

档案建立时同时保存每个成员订单各自的收货信息快照。建立以后，剩余清单直接按固定成员订单和未发数量计算，不再依赖这些订单当前是否仍能按手机号和地址聚成同一个开放组。成员后来修改收货信息时，系统把当前值与该成员自己的建档快照比较，明确提示哪些订单的收件人、手机号或地址已经变化；建档时本来就存在的成员差异不会被误报。继续发货沿用档案建立时保存的最终收货信息，不会把成员拆成新的发货轮次。成员后来取消或退款时仍保留在档案中，但标明当前不可继续发货。

待发货投影会排除已经属于开放档案的固定成员，再对其余新订单成组。因此，相同收货信息的后续订单既不会混入旧档案，也仍可像普通待发货组一样拆分或重新组合；界面不需要根据旧档案自行猜测或禁用调整功能。

界面按“待发货、部分发货、已完成”组织日常工作：尚未产生发货记录的开放组进入待发货；已经产生记录但仍有剩余数量的档案进入部分发货；剩余数量归零的档案进入已完成。每张档案卡先显示收货信息、关联订单、商品数量和进度，再向下展开多条发货记录与包裹。

发货组档案只负责组织和追溯，不取代发货记录。物流更正、未交寄撤销、后续售后、库存变化和资金事实仍精确关联发货记录、包裹以及订单商品数量；档案只是让这些独立事实在视觉和查询上保持同组关系。

旧版本只有零散发货记录，没有足够证据判断多条记录是否属于同一轮。升级时系统因此采用保守规则：每条旧发货记录建立一个已完成档案并保留其包裹、订单商品和数量，不依据可能重复使用的收货匹配编号猜测合并。历史数据宁可暂时分开，也不能错误混组。
