# 用明确生命周期事实管理来源截图文件

来源截图超过 90 天后由本机后台任务尝试转换为保持原始像素尺寸的高质量 JPEG。图片处理适配器必须先成功解码原图，再以固定高质量编码，重新解码结果并确认非空、像素尺寸一致且文件确实更小；任一检查失败都保留原文件和原数据库记录。新文件先写入来源截图目录并完成验证，数据库切换到新路径后才删除原文件，数据库更新失败则删除新文件并保留原图。

来源截图清理策略保存在当前数据目录中，默认永不自动删除，可选择 180 天或 365 天。策略只形成来源截图清理预览；批量清理必须展示候选数量和预计释放空间并由用户二次确认，确认时再次核对候选。单张来源截图也允许在明确确认后清理。清理先在当前数据目录的受管回滚目录建立并复验副本，保留原文件不动；数据库提交已清理状态后才删除原文件与回滚副本。数据库更新失败时只移除回滚副本，原文件始终保留；提交后异常退出遗留的原文件或回滚副本在下次维护时清除，且回滚目录不进入备份。

压缩与清理都不删除 `source_screenshots` 行，不修改原始内容指纹，不删除识别原文、来源快照、订单商品或订单当前值。已压缩行始终保留原始相对路径，清理时另记当时的当前文件路径，使异常退出后的原图、压缩图和回滚副本都能被后续维护定位；已清理行继续参与来源证据关系和原始指纹重复保护，但读取图片时明确返回“来源截图已清理”。

## 硬约束

### SL-01 失败不替换原图
- 图片解码、编码、尺寸复验、写入或数据库更新任一步失败时，不得丢失原文件或把记录标为已压缩。

### SL-02 清理必须确认
- 默认策略为永不自动清理；180 天或 365 天策略只产生候选，批量删除必须经过带预计释放空间的二次确认。

### SL-03 结构化证据保持
- 压缩或清理不得删除来源截图记录、来源快照、识别原文、订单或商品数据，不得改变原始内容指纹。

### SL-04 文件操作可恢复
- 删除文件前必须在同数据目录建立并复验回滚副本；数据库更新失败时保留原文件，成功后再删除原文件与回滚副本。

### SL-05 本机数据边界
- 原图、压缩图和操作临时文件只能位于当前数据目录；不得上传到新的外部服务或写入系统临时目录。
