# 分别记录退款、退货和售后进度事实

仅退款和退货退款继续使用同一套售后处理单与商品数量边界，但处理单只负责组织过程，不把退货运输、收到、检查或实际退款压成一个售后状态。仅退款建立退款申请，不创建退货记录；退货退款另建退货记录，并用不可变事件依次保留登记物流、实际收到和检查结果。收到退货不增加可销售库存，检查结果只作为未来库存模块可读取的事实。

退款申请属于待确认资金事项，固定保留申请金额。只有平台账单、实际支付或人工确认后才新增不可变资金记录，并保留可能不同的实际退款金额；确认退款不能由售后状态、退货签收或检查结果推断。取消售后只取消仍待确认的退款申请，不能删除已经发生的退货事实，也不能撤销已经确认的资金记录。

专用处理方式由领域动作推进：退货退款依次经过等待退回、等待检查、等待退款和待完成，仅退款从等待退款开始。每次动作与对应退货、资金事实及售后时间线在同一事务中保存。一般处理仍保留原有人工状态和商品数量修订能力；专用处理方式不能借此跳过必需事实。该结构为后续多轮补发、库存流水和完整财务模块提供稳定关联，但本阶段不提前生成库存变化或利润结果。
