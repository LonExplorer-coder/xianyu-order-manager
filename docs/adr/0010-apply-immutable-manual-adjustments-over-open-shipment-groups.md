# 以不可变调整事件覆盖开放发货组投影

系统把手工拆分或重新组合保存为本机不可变的发货组调整事件，并在每次查询时将这些事件覆盖到符合资格的订单当前值之上；不另造合并订单，也不改写任何成员原始订单。相比直接保存一份会过期的发货组副本，这一做法保留了人工意图和审计依据，同时让取消、退款、履约状态与订单修改继续通过动态投影生效；代价是查询时需要重放数量有限的本机调整记录。

跨不同发货匹配键的重新组合必须从当前成员订单中显式选择最终收货信息，否则整个调整原子失败，不保存含糊的开放组。每个订单的最新调整归属覆盖此前归属，因此一笔符合发货资格的订单在任何时刻最多属于一个开放发货组。

调整记录按本机数据库的写入顺序重放，不依赖可能相同的时间字符串决定先后。每次命令都携带当前成员快照；若操作前成员已变化，命令原子失败，用户需刷新后重试。

若跨发货匹配键重组中的最终收货信息来源订单不再属于待发货范围，系统不得继续使用已离开成员的收货信息，也不得保留无最终收货信息的跨键开放组。剩余订单暂时回到自动成组；来源订单重新符合资格时，最新人工意图可再次参与投影。

这些调整只适用于开放发货组，不会产生发货快照、改变履约状态或执行导出。已发货冻结、重打印与导出安全分别由后续阶段决定。
