# 允许功能开发先行但不放宽发布门槛

第一阶段的功能、自动化测试和双平台便携版基线已完成，但由于当前真实订单数量不足，无法立即完成至少 30 张私有金标截图的正式验收。为避免复制或伪造样本，产品决定在等待样本自然积累期间允许后续功能开发先行。

这一决定只调整开发顺序，不代表第一阶段已验收或发布。GitHub Issue #14 继续保持打开；不触发付费 OCR，不使用复制样本满足门槛，也不创建正式 Release。待真实样本足够后，必须针对当时最新的发布候选提交重新完成 #14 的私有金标、完整 CI 和双平台产物验收，不复用旧提交的发布证据。

后续开发仍遵守本机优先架构。平台交易状态、履约状态、快递公司和运单号只保存在用户选择的本机数据目录，不发送给 OCR 或其他云端服务；API Key 与 Workspace ID 的存储方式不变。功能 Issue 可以在开发和自动化验收完成后关闭，但关闭功能 Issue 不能被解读为阶段发布门槛已通过。
