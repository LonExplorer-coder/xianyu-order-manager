# 落定库存与采购首版管理范围

规格 002 第 10、13 节为库存与采购预留了实物流转对应表和职责边界，但首版的仓库粒度、库存展示、采购变更深度与未映射明细处理留给决策工单 #54。用户已拍板，结论如下。

## 决策

1. **首版单仓库、无库位**：所有库存视为存放在一个默认存货点，界面与数据结构不引入仓库或库位概念，出入库不选位置。将来出现第二个真实存货点时通过版本化迁移补充仓库维度，不为此预留空字段或配置项。
2. **库存视图六数全分列**：每个标准商品一行，分列展示四类真实库存状态（可销售、待检查、瑕疵品、报废）与两个参考数（已预留、采购在途），两组分区呈现，不提供合并的总数列。已预留从履约与发货事实派生（已释放进发货组尚未发出的数量），采购在途从已确认采购事实派生，两者不与实物状态混算。
3. **供应方退货与采购订单变更按计划全量实现**：一张采购订单支持分次到货并逐次记录实际数量与检查结果；瑕疵品退供应方保留独立记录（减瑕疵品库存，不回可销售）；采购订单变更或取消必须显式记录原因，不被需求重算静默覆盖。资金边界按规格 13.1：采购只产生待确认应付事项，实际付款归财务模块。
4. **未映射明细提醒 + 从映射起记账**：未关联标准商品的订单明细不静默扣减或增加库存，也不拦截确认发货；库存视图提供未映射明细提醒清单。确认映射的那一刻起开始记库存，之前的实物流转不回补（回补需要虚构历史期初数量，会制造假账）；新纳入管理的商品以一次期初入库（人工调整流水）录入现有存货。

## 影响

- #68 建立库存流水与四态统计时按本口径设计数据结构：流水记录商品、款式、数量、方向、发生时间、来源记录与唯一编号；已预留与采购在途为派生参考数，不落流水表。
- #69 接入实物流转：发货与补发扣减可销售、退货签收进待检查、检查结果分流可销售/瑕疵品/报废、拦截成功与运输丢件不动库存，全部遵循规格 10 的对应表。
- #70 采购模块按全量范围实现，分次到货的剩余在途跟踪是其中最复杂的部分，不砍。
- #71 预售退款重算只作用于未确认采购建议，不触碰已确认采购订单（规格 12.4 与 ADR 0037 一致）。
- 未映射明细的提醒入口与工作台待办的关系在 #68 实现时确定；提醒只呈现事实，不自动建立映射。
- 与 ADR 0030（显式商品映射）衔接：映射确认是开始记账的触发点，映射本身仍由校对流程维护。
