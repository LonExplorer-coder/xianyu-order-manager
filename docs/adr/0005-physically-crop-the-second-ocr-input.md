# 对第二次 OCR 使用物理裁剪的订单图

百炼 qwen3.5-ocr 的关键字段提取接口可以接收字段结构和文字提示，但当前公开参数没有输入 ROI、遮罩或边界框。把六个区域的纵坐标写进提示词只能形成软约束，模型仍能看到整张截图，并可能把订单详情下方的推广商品误写入订单字段。

应用第一次 `advanced_recognition` 仍发送完整原图，用文字坐标定位平台状态、收货信息、商品、金额、订单详情和底部履约操作六区。布局有效时，主进程使用 Electron `nativeImage` 在本机按半开区间 `[0, excludedPromotion.startY)` 保留图片顶部，物理移除推广区和底部操作区；第二次关键字段提取只接收这张裁剪图以及前五区字段结构。底部“去发货”等履约信号只从第一次定位文字恢复，不要求第二次模型重复读取。

百炼内置关键字段提取任务已有默认提示，因此第二次请求不再附加文字提示。字段结构只使用简短的名词性说明，不写入“原样复制”“不得包含”“返回 null”等命令句；这些说明仍属于生成式模型输入，不能视为强类型约束。应用必须继续用第一次定位证据逐字段校验二次结果，并把字段说明回显、模块结构异常和跨区内容拦截为待确认项。

该设计保持每张截图正常流程恰好两次远端调用，不增加第三次复核。裁剪、重编码或大小校验失败，或者运行环境没有提供裁剪器时，应用不得把完整原图降级发送给第二次关键字段提取；流程只保留第一次定位结果，标记定向复核未完成并进入人工确认。PNG 与 JPEG 使用 Electron 跨平台保证的原生解码；其他格式无法裁剪时走同一安全降级。

物理裁剪只隔离第二次结构化提取。第一次坐标定位仍会把完整截图发送给用户配置的百炼服务，因此它不是对推广区域的全流程隐私遮罩。
