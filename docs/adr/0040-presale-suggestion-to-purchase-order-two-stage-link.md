# 预售建议与采购订单的两段式衔接

ADR 0037 第 4 条约定「本版建议确认即视为在途，阶段三采购订单落地后由其承接」。#70 已落地采购订单域（草稿→确认→分次到货→供应方退货），#71 把建议与订单连接起来时必须回答：建议确认、转入订单、订单确认三个动作各自算多少覆盖。本次口径如下：

## 决策

1. **覆盖口径随单走**：已确认建议（未转单）按意向计入需求覆盖；转入采购订单后建议转为 converted 态并关联订单，自身退出覆盖，改由订单口径承接——只有**已确认**的计划关联订单计入采购在途（草稿不形成在途、不立应付，与 #70 一致）。同一需求不会被建议与其订单重复覆盖。
2. **转单创建草稿订单，仍需人工确认**：转入动作创建关联该计划的草稿采购订单；覆盖空窗（建议已转、订单未确认）期间缺口暂时回升，工作台列出关联订单（含草稿状态）并提示勿重复下单。规格 12.3「用户确认后才生成采购订单，系统不能自动下单」在两侧都保持显式。
3. **缺口公式**：`剩余缺口 = 有效需求 − 可用现货 − 计划关联已确认订单在途 − 已确认建议（未转单）`。可用现货 = 可销售数量减去计划外待发货订单的已预留数量（未释放计划成员不占预留，其需求即本计划需求，不会重复扣减）；跨计划共享同批现货仍是已知限制，#72 验收走查后维持按商品共享、不做计划间分配（需要时另立工单）。安全余量维持未实现（#72 验收走查结论：无实际需求依据，需要时另立工单）。
4. **多采购风险与缺口同口径**：现货、在途与已确认建议合计超出有效需求即预警并给出件数与处理选项（减少数量、取消未到货部分、到货后供应方退货或保留为普通库存）；退款重算只收缩未确认建议，绝不改写已确认订单，供应方变更走订单显式变更/取消/退货记录。
5. **converted 是终态**：已转建议不能取消、不能重复转入；订单取消后缺口回升但建议保持转态历史，新需求重新生成建议。转入数量可小于建议数量（剩余意向需重新生成建议），也可超过（由多采购风险兜底），均为用户显式选择。
6. **计划关闭/已释放后不能转入**：与建议确认同一守卫口径。

## 影响

- 建议表新增 converted 态与 `purchase_order_id`（schema v57），订单表新增 `plan_id` 计划归属；普通补货订单 plan_id 为空，不进任何计划覆盖。
- 需求视图按商品对照需求、退款、现货、在途、到货、建议与剩余缺口，并列出计划关联订单（`linkedPurchaseOrders`）。
- ADR 0037 第 4 条的「建议确认即视为在途」由本决策取代：意向覆盖只到转单为止，之后以订单为准。
