# 履约计划以显式释放控制订单发货资格

预售和团购发生在发货组形成之前，系统内部统一称为履约计划。普通现货订单不经过履约计划，继续直接进入开放发货组；只有用户显式加入履约计划的订单才受释放闸门控制。履约计划记录类型、名称、计划条件、预计发货时间和当前状态，订单归属与状态变化都以带原因的不可变事件保存，当前归属与计划状态只是事件的投影。

一笔订单同一时刻最多归属一个未释放的履约计划。加入、退出和释放都必须给出非空原因；退出与已释放的订单重新获得发货资格。发货资格只回答“当前能否进入开放发货组”，不复用平台交易状态或订单履约状态冒充：未释放的计划成员订单不得出现在发货候选、开放发货组和待发货导出中，订单自身的履约投影不受影响。

针对尚未确认的释放与分配规则（issue #53），首版采用以下保守默认，后续可由用户决策收紧或放宽：

- 释放粒度：整单释放。多商品订单只备齐部分商品时整单等待，不拆分释放；需要部分发货时先退出计划再按普通订单处理。
- 释放方式：人工确认释放。到达预计发货时间或团购达到成团数量只让订单“具备释放条件”并在工作台提示，不自动释放。
- 库存分配顺序：未来接入库存时按系统订单编号先到先得。
- 采购提醒：默认人工选择需求生成采购建议，不自动提醒、不自动下单。
- 安全余量：未来接入时按全局设置，不按商品或计划分别配置。

履约计划只负责发货前的释放闸门，不向库存、采购或财务模块写入任何事实；需求、预留和资金事项由后续模块读取计划事实后各自记录。
