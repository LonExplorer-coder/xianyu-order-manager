# 用短生命周期局域网手机上传会话接收来源截图

桌面端只在用户显式开启手机上传会话时启动一个临时 HTTP 服务，并绑定当前可用的私有 IPv4 地址和系统分配的随机端口。二维码只携带高熵会话令牌；手机仍须输入独立的临时访问码，授权后才能提交最多 50 张受支持图片。服务默认关闭，到期、立即关闭、关闭全部应用窗口、切换数据目录或退出应用时销毁；上传完成后复用现有来源截图暂存与识别批次入口，不建立第二套队列。

手机正在提交的文件先写入当前数据目录中的受管 `.mobile-upload-staging` 目录，经过数量、类型和大小校验后再交给既有来源截图暂存入口；成功、失败、关闭或到期都会清理本次暂存，应用下次开启手机上传会话时还会先清理异常退出遗留内容。该目录不进入备份，也不使用系统临时目录保存来源截图副本。

手机页面只包含授权与上传能力。服务不暴露订单、来源截图历史、设置、导出或其他桌面接口；未知路径、缺少或错误令牌、错误访问码和过期请求都按未授权处理。临时令牌、访问码与授权状态只存在于主进程内存，不进入订单数据库、数据目录、备份、日志、错误或界面持久化状态。

局域网 HTTP 无法提供受公共证书信任的传输加密，因此该能力只适用于用户信任的同一局域网，并通过显式短期开启、高熵二维码令牌、独立访问码、请求体与文件数量限制及立即关闭缩小暴露窗口。若未来需要跨互联网访问、长期后台监听或手机端订单管理，必须重新决策传输加密、身份认证与远程数据边界。

## 硬约束

### MU-01 默认关闭且短时有效
- 手机上传会话只能由桌面端显式开启，并必须自动到期且支持立即关闭。

### MU-02 双重临时授权
- 二维码中的高熵会话令牌和用户输入的临时访问码必须共同有效；任一缺失、错误、过期或已关闭时不得访问上传页或提交文件。

### MU-03 仅上传
- 手机页面和 HTTP 服务只允许提交来源截图并返回本次识别批次摘要，不得读取、搜索、编辑或导出任何订单数据。

### MU-04 复用既有识别批次
- 通过手机接收的文件必须进入现有持久化暂存与识别批次入口；不得绕过批次上限、图片校验、重复保护、OCR 用量闸门或待确认规则。

### MU-05 临时秘密不持久化
- 会话令牌、临时访问码和手机授权状态不得写入订单数据库、数据目录、备份、日志、错误或版本库。

## 需要重新决策的变更

### MU-R01 跨互联网访问
- 条件：手机上传服务需要通过公网、中继、云端隧道或外部托管访问。

### MU-R02 长期后台监听
- 条件：应用启动后默认或长期开放手机上传端口，或关闭全部应用窗口后仍保持可访问。

### MU-R03 手机端业务管理
- 条件：手机端需要读取、搜索、编辑、导出订单或访问来源截图历史。
