# 预留即占用：可用现货口径与释放备货闸门

ADR 0036 拍板「有限库存按平台交易时间优先」，并以需求缺口提示替代备货硬闸门（阶段二过渡，归阶段三库存模块）。#68/#69 落地库存流水后，「已预留」只是待发货订单的镜像参考数，不阻止任何占用：同一批现货可以同时被现货订单与预售释放重复计算，形成一货多卖。用户拍板（2026-08-19）改为「预留即占用」：预留货仍在可销售库存里未发出，但其他交易不得再计算或动用这批货。

## 决策

1. **可用现货是统一的占用口径**：`可用现货 = 可销售 − 已预留`（已预留沿用 #68 镜像口径：计划外与已释放的待发货订单、扣发货前退款与已发出；未释放计划成员不占预留，其需求由履约计划承接）。库存页按商品展示可用现货，已预留超过可销售时标「已超卖」。
2. **释放备货闸门（issue #119）**：释放预售/团购成员前按商品核对「释放成员净需求（数量 − 发货前退款）≤ 可用现货」，不足则拒绝并列出每件商品缺口数；勾选「我知悉可用现货不足的缺货风险，强制释放」可放行并在释放事件负载留痕（stockShortageAcknowledged）。已超卖（可用为负）时同样全部暂停，补货前不新增任何占用。未映射商品的成员不参与核对。
3. **出库类操作按可用现货防呆**：人工出库与供应方退货作用于可销售状态时，防呆从「该状态存量」收紧为「存量 − 已预留」，不能动用被待发货订单占用的数量；待检查/瑕疵/报废状态防呆不变。发货确认仍按 #69 口径记录真实流转、不做账面防呆（占用闸门在其上游）。
4. **取代 ADR 0036 决策 2 的分配方向**：有限库存由「平台交易时间优先」改为「先占先得」——谁的占用先形成（现货订单先到、预售成员先释放）谁拥有这批货；后到的一方看到缺口，通过补货、下一批到货或协商解决。安全余量仍未实现（#72 确认归属）。
5. **预售缺口沿用同一口径**（#71 已实现）：现货覆盖 = min(需求, 可用现货)；跨计划共享同批现货仍是已知限制，按商品分配归 #72 范围确认。

## 影响

- 释放操作从此与库存联动：验收与冒烟等既有流程需先备货再释放；零库存释放会因闸门被拒。
- 释放事件负载新增 stockShortageAcknowledged 键（仅强制放行且确有缺口时写入），事件视图透出该标记并在工作台显示。
- 「先占先得」不回溯改写历史：已形成的占用不重排；超卖一旦出现以补货收敛，不做强制回收。
- 已知边界：关闭计划使未释放成员退出并恢复现货发货资格，是用户显式终止计划的动作，不等同释放、不设闸门；售后补发登记到实际发出之间无占用登记，其现货仍计入可用现货（补发占用概念待后续库存分配机制统一）。
