# 预售需求投影与采购建议事实

预售订单进入履约计划后即形成采购压力，但系统此前没有任何发货前的商品数量级退款事实，也没有采购建议的记录形态。ADR 0031 只交付了释放闸门，明确履约计划不向库存、采购或财务写入事实。本次（issue #64）在履约计划之上叠加预售需求视图与采购建议，遵循以下口径：

## 决策

1. **有效预售需求是只读投影**：对每个预售计划，按未释放且未退出的成员订单实时累计商品数量；整单平台退款或取消的订单全部计入「退款/取消」桶，未退款订单再扣除逐项发货前退款数量。回收站订单完全退出需求池。已释放订单退出需求池，发货后的退款属于售后域，不再回到发货前需求。
2. **发货前退款是不可变事实**（`fulfillment_refund_events`）：精确到订单商品与数量，登记时校验成员归属与剩余可退数量；订单一旦整单退款（平台交易状态），其逐项退款被整单状态吞并，不允许再登记。
3. **整单退出订单状态触发未确认建议收缩**：订单平台交易状态改为退款或取消时，若它是某预售计划的未释放成员，系统按商品重算并把未确认建议数量收缩到 `有效需求 - 已确认在途`（最新批次先吸收，归零即取消并留原因事件）。两条入口都触发：订单列表的手工状态批量更新，以及重新导入截图后等价合并为订单更新；已确认建议永不改写，超出需求时给出多采购风险提示。
4. **采购建议三态**（draft/confirmed/cancelled，`purchase_suggestions` + 不可变事件表）：创建时数量不得超过 `未覆盖需求 - 未确认建议`；确认后计入采购在途数量；取消（含已确认后取消）需原因并留事件。本版建议确认即视为在途，阶段三采购订单落地后由其承接。
5. **未映射标准商品的明细不进需求与缺口**：单列展示并提示人工关联，绝不静默生成建议。
6. **安全余量按 ADR 0036 留待阶段三**：本版缺口 = 有效需求 - 已确认在途；已分配现货与到货待检查由库存模块提供，未接入前按 0 展示。
7. **需求提醒阈值挂在计划上**（`fulfillment_plans.demand_alert_threshold`）：任一商品未覆盖需求达到阈值时在工作台列出提示，不弹窗、不自动下单。

## 影响

- 每次需求相关操作返回最新需求视图，前端无需单独刷新通道。
- 团购计划（#65）将复用需求投影骨架，把条件性需求与成团转化接进来。
- 履约计划服务与需求服务共享计划表但写入边界清晰：计划域只写成员与计划行，需求域只写退款事件与建议表。
