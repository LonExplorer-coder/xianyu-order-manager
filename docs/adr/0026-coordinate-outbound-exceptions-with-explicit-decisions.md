# 以明确处理选择协调正向物流异常

正向包裹在运输中可以直接建立售后，不以物流异常为前提。丢件、错投、破损或其他物流异常进入已确认阶段后，系统不猜测买家侧结果，而要求用户在继续等待调查、追回或重新派送、仅退款、直接补发或退款并补发中明确选择。每次选择与变更按异常事项、包裹、售后商品和数量保留不可变事件。

退款、补发和承运索赔是三条可并行的事实链。选择补发或退款并补发时，必须为当前异常建立新的售后处理轮次，之后由该轮次建立独立补发记录；不改写原发货记录，也不伪造已发出事实。一个异常事项只关联一个补发轮次，同一包裹后续独立异常可建立各自轮次。承运索赔继续引用原物流异常，不因买家已退款或补发而结束。

拦截申请、成功和失败仍是独立事实。拦截成功不等于卖家已收回实物；只有原正向包裹已记录可信的实际退回，才能登记拦截退回检查。该检查直接关联原包裹与所属售后商品数量，不为了复用退货流程而伪造买家退货记录。拦截失败且买家已签收时，只能显式转为买家退回或仅退款，不能沿用已失效的在途拦截意图。

这一决策保持正常运输事实、物流异常、买家侧处理、补发和索赔的长期边界，也确保合装包裹中一笔订单的商品异常不会泄漏到其他订单。本阶段只在现有发货记录和售后处理单中提供必要待办、风险、并列事实与历史，不提前建立跨模块统一工作台。
