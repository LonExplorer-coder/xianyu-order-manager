# 以明确处理选择协调正向物流异常

正向包裹在运输中可以直接建立售后，不以物流异常为前提。丢件、错投、破损或其他物流异常进入已确认阶段后，系统不猜测买家侧结果，而要求用户在继续等待调查、追回或重新派送、仅退款、直接补发或退款并补发中明确选择。每次选择与变更按异常事项、包裹、售后商品和数量保留不可变事件。

退款、补发和承运索赔是三条可并行的事实链。选择补发不会暗中取消退款申请；用户可以更改异常处理选择，也只能通过显式、可审计的资金动作取消退款。已取消的退款重新申请时，重开原资金事项并记录前后金额、原因和时间，不用新增重复资金事项覆盖历史。选择补发或退款并补发时，必须为当前异常建立新的售后处理轮次，之后由该轮次建立独立补发记录；不改写原发货记录，也不伪造已发出事实。一个异常事项关联它的初始补发轮次以及未交寄作废后的重试链；重试轮次始终沿用所属异常的最新处理选择，同时只保留精确的未完成数量。同一来源商品的多个异常不能重复占用超过售后所属数量。补发包裹后续发生独立异常时，必须以该补发记录和实际受影响商品为新轮来源。多个必要补发轮次必须分别建立并全部完成，当前待办优先指向最早的未完成轮次。补发记录已建立后，不能用变更处理选择抹去该事实：未交寄可显式作废，保留旧记录并为作废商品数量建立新的待补发轮次；已交寄要走拦截或后续处置。承运索赔继续引用发生异常的物流事项，不因买家已退款或补发而结束。

拦截申请、成功和失败仍是独立事实，并且必须绑定具体包裹，不能把 A 包裹的拦截结果用在 B 包裹上。拦截成功不等于卖家已收回实物；只有同一原正向包裹已记录可信的实际退回，才能登记拦截退回检查。该检查要精确覆盖该包裹在当前售后中的全部商品数量，不为了复用退货流程而伪造买家退货记录。检查后如果选择重新发出，依然使用新的补发轮次和发货记录。拦截失败且买家已签收时，只能显式转为买家退回或仅退款，不能沿用已失效的在途拦截意图。

同一售后出现多个已确认正向异常时，当前待办优先呈现还没有处理选择的事项，已选择事项仍可按各自异常进入并更改。已完成或已取消的售后单不能被新的正向异常选择重新打开；新的买家侧问题需要建立新售后单，物流和承运索赔事实则可继续独立追加。

这一决策保持正常运输事实、物流异常、买家侧处理、补发和索赔的长期边界，也确保合装包裹中一笔订单的商品异常不会泄漏到其他订单。本阶段只在现有发货记录和售后处理单中提供必要待办、风险、并列事实与历史，不提前建立跨模块统一工作台。
