# 从源事件统一投影物流与售后运营信息

订单、发货档案和售后处理同时涉及正常运输、物流异常、买家侧处理、退货实物、退款、补发和承运索赔。任选其中一个状态作为“全局结论”，都会遮蔽现实中仍在并行的其他事实；如果各界面再各自选取“最后一条”，还会让不同入口显示不同结论。

因此，不新建另一套持久化状态机。系统从发货记录、包裹物流事件、物流异常事项、售后处理单、退货包裹、退款事项、补发记录和承运索赔的源事件即时生成订单运营投影。投影固定分为四层：仅一项最高优先级当前待办、未解决风险、并列当前事实和默认折叠的完整不可变历史。待办优先级为明确期限、资金风险、实物失控风险、普通跟进；其余待办显示数量并能定位到对应发货记录、包裹或售后处理单。

商品和数量是跨流程投影的最小边界。包裹级事实只影响该包裹所属商品，商品级异常或索赔只影响明确选中的商品与数量。合装包裹按订单过滤受影响商品，不把一笔订单的异常、索赔、待办或风险泄漏到另一笔订单。

正常运输与物流异常、买家侧售后与承运索赔、资金与实物可以同时存在，互不覆盖。活动事实不会因另一链路的最后一条记录而消失。已完成、已取消或已解决的流程可继续补录晚到事实，但不因补录而重新打开。完整历史直接读取不可变源事件，不从当前末态反推，也不用最后一条摘要代替过程。

旧版曾把丢件、破损、错投或签收争议存入物流状态。数据升级仅执行一次保真转换：恢复最后可信的正常运输事实，并把旧异常转为独立物流异常事项与时间线。运行时只允许待承运方接收、运输中、已签收和已退回四种正常运输状态；不保留旧混合状态的运行时写入入口、兼容分支或回退路径。

这一决策让订单详情、发货档案、售后面板和可配置运营概况共用同一口径，同时保持库存和财务仍只消费已确认的退货检查、实际退款、补发和承运赔付事实，不在本阶段扩展库存流水或财务总账。
