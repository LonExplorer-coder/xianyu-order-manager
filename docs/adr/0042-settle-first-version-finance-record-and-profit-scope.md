# 落定财务首版记录与核算口径

规格 002 第 11、14 节给财务管理预留了「已确认和待确认的资金变化」这一职责边界，但首版币种、确认方式、成本口径与利润维度留给决策工单 #55。本决策按规格与既有系统事实推定落定（全库金额均为分单位整数、无任何币种与税务概念、采购应付款已有 #70 桩表），未逐条请用户拍板；如与实际经营不符，开新工单推翻本决策即可（先例：ADR 0036 决策 4 被 ADR 0041 取代）。

## 决策

1. **首版只支持人民币与人工确认，不处理税务与发票**：每笔资金记录仍保存币种字段（ISO 代码），但首版校验只放行 `CNY`。确认来源只有人工确认一条路径——平台账单与实际支付没有自动对接，都由店主照单录入后人工确认。税务、发票、多币种汇率不建任何概念，出现真实需求时再版本化迁移。
2. **定金、尾款与供应方账期不进首版**：应付款在采购订单确认时产生（#70 已落 `purchase_payables`：数量 × 确认单价）。实际付款用「部分确认」表达——付多少记多少，定金与尾款天然可表示，不需要专门的分期计划结构；账期（到期日）不加字段。应付款金额变化只能走采购订单显式变更（#70 已实现），不被资金模块反向改写。
3. **商品成本口径 = 已确认采购成本，按到货批次单价记录，库存检查结果决定成本去向**：商品成本不取自成交价或手工估价，唯一来源是采购订单确认的单价。到货检查分流成本：转可销售保留成本；退供应方冲回（负向资金记录）；报废计损失，成本不回流利润。期初入库与人工入库不自动携带成本，需要时人工补记采购成本类支出。依据规格 11「商品退回后成本如何变化，要等待库存检查结果」。
4. **利润首版以订单为主维度，商品为汇总下钻维度；发货记录与售后处理单只作来源记录参与追溯，不独立核算利润**：成交、结算、退款、各类运费、拦截费用与赔付的资金事实都挂到订单（或其子记录）；采购成本经商品流转关联。商品维度按标准商品汇总毛利。把利润算到发货记录或售后单头上会双计（一次补发同时关联原发货与售后单），故两者仅出现在「这笔钱从哪来」的追溯链上。

## 资金类型词汇（规格 11 全量清单，进入 #73 枚举设计）

订单成交金额、平台实际结算收入、平台服务费、首次发货运费、退货运费、补发运费、退款（部分或全部）、物流拦截费用、丢件赔付或承运方理赔、商品采购成本、其他人工费用或补偿。成交金额 ≠ 平台结算 ≠ 最终利润，三类金额独立记录、独立汇总。

## 影响

- #73 建立待确认资金事项与资金记录时按本口径设计：两张独立事实表、币种字段只放行 CNY、确认来源为人工、幂等键绑定业务事实、部分确认与冲正不覆盖原记录。
- #74 接入业务资金变化时，退款与赔付先产生待确认事项，人工确认后才成为资金记录；采购付款消费 `purchase_payables` 并支持部分支付。
- #75 利润视图按订单主维度 + 商品汇总下钻；未确认事项单独列示，不混入已实现利润。
- 售后处理单里的退款记录与赔付金额（#63、#65 已落）保持为业务事实，财务模块读取它们生成待确认事项，不反向确认。
