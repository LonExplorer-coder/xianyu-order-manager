# 财务接入：钩子立账清单与业务详情资金区

#74 把订单、售后、物流与采购的资金变化接入 ADR 0043 的资金事实双表。接入方式沿用 #69 库存钩子先例：业务事务内幂等立账，只产生待确认事项，绝不自动生成资金记录。

## 决策

1. **自动立账钩子只有两处**：
   - 售后处理单的每笔实际退款（confirm_refund 落 legacy `financial_records` 的同一事务内）→ 退款待确认事项，锚点是该笔退款记录 id；部分退款、补退每笔各立一条。
   - 承运索赔同意赔付（LogisticsExceptionService.resolveClaim，覆盖正向丢件与退货两个方向）→ 丢件赔付待确认事项，锚点是索赔 id；拒赔不立账。
   - 确认实际赔付（confirm_carrier_compensation）只更新业务侧到账事实，不自动确认资金——到账确认仍在资金模块人工完成（到账前保持待确认）。
2. **不自动立账的业务与理由**：
   - 订单成交金额：留在订单本身（规格 14 职责边界「原始订单保存订单当前值」）。付款状态变化不进资金队列；订单详情资金区把成交金额（订单参考值）与平台结算记录分列展示，分别记录、分别汇总。
   - 发货前逐项退款（fulfillment_refund_events）：只有数量事实、无金额事实，不立账；订单级资金变化由平台交易状态与售后实退承接。
   - 供应方退货：退货事实不等于退款承诺（CONTEXT「供应方退货」词条既有口径），退款由退货行「记供应方退款」人工录入。
3. **商品采购成本双向**：支出 = 采购付款，收入 = 供应方退款/冲回（类型净额即采购净成本，供 #75 利润视图取数）；方向选择在采购成本与其他人工费用两类放开。
4. **直接录入可携带来源**：六类业务来源（订单、发货记录、售后处理单、采购订单、供应方退货、物流异常）可选、成对提供并校验存在；各业务详情页的「记一笔」入口预填并锁定来源——订单详情记平台结算/服务费、售后面板记运费/拦截费、采购卡片登记付款、供应方退货行记退款、发货记录卡记首发运费。资金页直接录入保持无来源。
5. **业务详情只读资金区**：按来源懒加载（售后处理单聚合三类锚点：售后单 id、退款记录 id、本单退货的索赔 id）；采购卡片合并展示挂采购订单的付款与挂其供应方退货的退款，净支出与待确认应付并列；全部只读，确认/冲正只在资金页进行。

## 影响

- 状态变化绝不静默确认资金：全部钩子只写待确认表；资金记录的唯一入口仍是人工确认、人工录入与人工冲正。
- `purchase_payables` 维持 #70 口径独立展示（应付随采购数量变更重算），实际付款与供应方退款记在资金事实并按来源关联采购订单；两者并列不互相改写。
- 迁移旅程测试降级经过 v58 前需清空钩子产生的待确认数据（`clearVersion58FundsData` 测试助手）。
- #75 利润视图按来源取已确认记录；成交金额列取自订单本身。
