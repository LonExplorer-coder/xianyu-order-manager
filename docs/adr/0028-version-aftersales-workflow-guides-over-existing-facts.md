# 在既有售后事实之上提供版本化流程向导

用户需要按“仅退款”、“退货退款”、“换货”或“丢件处理”等场景理解复杂售后，但不能让每套流程各自产生一组退款、退货、补发或索赔数据。为此，售后流程定义为对现有领域动作的有限、版本化操作向导，不是另一套业务状态机。

系统提供七套只读预置流程，预置可停用或复制为自定义流程，不允许原地改写。自定义流程只使用系统定义的步骤类型、字段要求和布尔条件；一个步骤最多一个条件，不提供循环、任意脚本或自由代码执行入口。步骤设置决定界面中的顺序、当前焦点和需要核对的字段，不绕过底层业务规则。

每次保存自定义流程都追加一个不可变模板版本。售后处理单建立时必须选择已启用的模板，并以不可变事件固定当时的模板标识和版本。修改模板只影响之后的新处理单。进行中的处理单改变场景时，另行追加流程选择事件；如需换货或补发，则建立新的后续处理轮次。已有退款、退货、补发、物流异常和索赔事实不会因向导改变而删除、覆盖或重新猜测。

该边界让流程管理保持容易理解，同时使物流、资金、退货检查、补发和索赔仍然只由各自的真实事实驱动。
