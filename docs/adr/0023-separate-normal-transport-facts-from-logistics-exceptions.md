# 分离正常运输事实与物流异常事项

包裹的正常运输事实只保存待承运方接收、运输中、已签收和已退回，用来回答包裹最后可信的承运位置进展。丢件、签收争议、破损、错投和其他异常保存为独立物流异常事项；每个事项关联运输方向与来源包裹，按包裹或商品数量记录影响范围，并以待核实、调查中、已确认、已找回和已解决组成不可变时间线。异常推进不能覆盖正常运输事实，已找回或已解决也不能删除此前异常、退款或承运索赔历史。

正向发货与退货运输共用这一事实模型和证据约束：没有承运方揽收证据不能确认丢件，已有可信收到证据不能通过普通操作确认丢件或回退到收件前结论。用户确需修复错误登记时使用带非空原因和发生时间的更正入口；物流异常本身只提供上层处理方向的判断依据，不自动生成退款、补发、库存变化、责任或售后状态转换。

旧版把异常混入物流状态的数据在一次数据库事务内保守升级。已有异常事件按原类型、影响商品和时间建立独立事项；只有旧版明确记录的丢件结论映射为已确认，其他异常停在待核实，后续正常运输事件只把事项推进为已解决。迁移不会推断商品控制方、责任或实际收到；失败时回滚全部新表和数据，成功后由迁移版本保证重复启动幂等。旧混合事件转存为不可变升级证据，运行时只接受新的分离模型。
