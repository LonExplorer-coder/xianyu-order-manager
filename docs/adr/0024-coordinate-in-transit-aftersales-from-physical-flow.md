# 依据实物流转协调在途售后

退货退款处理不再由“已建立售后”直接推导“等待买家退回”。系统按售后所选商品读取原正向包裹的当前正常运输事实和已确认丢件事项，形成动态的实物控制关系；商品未由买家控制时，建立者必须明确选择继续等待、申请拦截、约定拒收、仅退款或补发，不创建退货包裹。只有原正向包裹已签收且用户选择买家寄回时，才进入等待退回。

售后处理方向同时保留当前值与不可变选择、转换事件；切换为不需要处理方向的流程时，还要追加明确的结束方向事件。每条事件都记录原方向、新方向或明确空值、原因和发生时间。拦截事项以另一条不可变时间线分别记录申请、成功和失败；拦截结果或后续签收只改变可选方向与待办风险，必须经显式转换才改变当前方向。这避免把承运回复误当成退回实物，也保留事后说明为什么更改处理意图的证据。

处理方向不写回原正向包裹、发货快照、平台交易状态或资金事实，也不自动退款、补发或判责。确认丢失后只提示继续调查、仅退款或补发；本决策中的“补发”仅产生待办，真实的新发货记录仍由后续补发履约能力建立。该边界是长期数据归属与审计约束，改变后需要数据迁移并会改变历史解释，因此作为独立架构决策固定。
