# 将历史导入建模为独立订单来源

#22 的历史导入与截图识别共用原始订单、订单商品明细、来源快照、订单更新、自定义字段和商品标准化规则，但不伪造来源截图、识别批次或订单草稿。来源快照因此显式区分“截图”与“历史导入”：前者必须关联草稿和截图，后者必须保存来源文件名和非空原工作表行号，两种组合由数据库约束互斥。

导入固定按“选择工作表与列对应 → 预览新增、更新、重复和错误 → 确认”执行。平台、卖家账号和平台订单编号是必填身份，缺失时作为错误行跳过，不生成临时订单编号。同一身份的多行合成一笔多商品订单；其中任一行错误或订单级字段不一致时，整笔不导入，避免建立残缺订单。错误行可按原表头下载，但不写入业务数据。

预览标识同时覆盖列对应、解析结果和当前已有订单的版本与差异。确认前重新计算；期间订单变化时拒绝陈旧预览。同一身份内容等价时跳过且不追加来源；内容变化时，预览和确认共用同一个稳定商品配对结果，并在预览标识生成前先应用订单版本、未映射可选列保留、更高优先级数量、已有商品标识与标准化关联和履约事实保护，不另建一套覆盖规则。

新增订单使用已有自定义字段默认值并校验必填值，同时复用精确标准商品和有效商品映射自动关联。工作簿在 Excel 解析前检查 10 MB 文件上限、内部文件数和解压后内容上限，并在解析后限制工作表、行和列数。单笔订单最多聚合 100 个商品行，商品小计超出安全整数范围时在预览阶段就归入错误行，避免单笔异常在确认事务中回滚其他有效订单。
