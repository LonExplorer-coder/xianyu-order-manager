# 落定履约释放粒度与库存分配、采购提醒、安全余量口径

ADR 0031 为履约计划释放与后续库存采购规则定了首版保守默认，并预留「后续由用户决策收紧或放宽」。决策工单 #53 已由用户拍板，结论如下，其中分配顺序与安全余量两处调整了 ADR 0031 的默认值。

## 决策

1. **释放粒度维持整单释放**：多商品订单任一商品未备齐时整单等待，不按商品拆分释放；确需部分发货时先退出计划按普通订单处理。与 0.2.42 已交付行为一致。
2. **有限库存分配顺序按平台交易时间优先**：取代 ADR 0031 的「系统订单编号先到先得」默认。平台交易时间沿用既有回退链（付款时间 → 下单时间 → 入库时间，毫秒值），早者优先；时间相同的并列订单按系统订单编号从小到大决定，保证结果确定。
3. **采购提醒为人工选择 + 数量阈值 + 交期提醒的组合**：默认人工勾选未覆盖需求生成建议；未覆盖需求累计达到阈值时在工作台提示；供应方交期提醒依赖阶段三采购模块的交期数据，落地时机跟随该模块。所有提醒只在工作台呈现，不弹窗、不自动生成采购订单。
4. **安全余量按商品设置**：取代 ADR 0031 的「按全局设置」默认。每个标准商品可单独配置安全余量，未配置的商品回退全局默认值；不按履约计划单独设置。

## 影响

- 阶段二 #64 落地人工选择与数量阈值提醒；交期提醒的实现归入阶段三采购模块。
- 阶段二 #66 落地释放执行口径：整单释放粒度维持；订单工作台的待发货计数与待发货筛选同样排除未释放的计划成员；已取消或退款的成员订单不能释放，需先带原因退出计划。
- 释放的备货与时间条件按规格 12.3 的「或」语义执行：人工确认本身是独立的释放条件，未到预计发货日也可人工释放，时间条件只影响「具备释放条件」显示态与待办提示；阶段二没有库存模块，备货条件以需求视图的未覆盖缺口提示替代，库存分配后的硬闸门归阶段三库存模块落地。
- 释放后的订单按既有收货匹配键进入开放发货组并尊重手工拆分/合并，发货与售后仍由发货记录和售后模块处理，不回写履约计划事件。
- 分配顺序与安全余量在阶段三库存与采购接入时按本口径实现，本阶段只记录不实现。
- 退款后的需求重算与多采购风险提示仍按规格 12.4 执行，与本决策正交。
