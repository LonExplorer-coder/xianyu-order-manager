# 资金事实：双表分离、幂等立账与冲正不覆盖

#73 建立独立于订单、物流与售后状态的资金事实。范围与币种口径由 ADR 0042 落定，本 ADR 记录事实结构本身。

## 决策

1. **待确认与已确认双表分离**：`finance_pending_items` 只保存业务事实立账的预计资金变化（状态 pending/cancelled）；`finance_records` 只保存人工确认后的收入与支出。业务完成最多产生待确认事项（幂等立账），人工确认是唯一的跨表路径——业务状态不能自动制造资金记录。
2. **幂等锚点是 (来源类型, 来源标识, 类型)**：来源标识必须指向具体业务事实（某次退款记录、某个售后处理单的某次赔付），不是聚合计数；同一事实重复提交用 `INSERT OR IGNORE` 无操作。其他人工费用或补偿没有业务来源可挂，直接录入资金记录，不建待确认事项。
3. **部分确认按净额回补**：确认生成不可变记录，剩余待确认 = 事项金额 − 该事项名下全部记录按方向加权的净额。因此冲正一笔经待确认事项确认的记录，剩余可确认金额自动回补，可重新确认；取消只取消剩余金额，已确认部分与记录保留。
4. **冲正不覆盖原记录**：冲正是同类型、反方向的新记录，金额不超过原记录未冲正余额，允许链式（冲正的冲正 = 恢复）。`finance_records` 整表不可更新删除；待确认事项的事实列（类型、方向、金额、来源、说明等）由触发器保护不可改写，仅状态与取消留痕列允许更新。
5. **类型、方向与币种**：类型枚举采用规格 11 节全量清单（成交金额、平台结算、服务费、三类运费、退款、拦截费、丢件赔付、采购成本、其他人工费用）；方向按类型固定（成交/结算/赔付为收入，其余为支出），仅其他人工费用双向可选；每笔记录保存币种但首版只放行 CNY，确认来源只放行人工确认。
6. **汇总按类型分列、待确认余额独立**：资金视图按 11 类型分别列收入、支出与净额，总净额是各类型之和；待确认余额单独合计，不混入已确认净额。每笔记录经待确认事项或直接录入追溯到业务来源记录。

## 影响

- #74 接入业务资金变化时直接调用立账接口（幂等，可安全重放）；`purchase_payables`（#70 桩表）与统一资金事实的桥接方式在 #74 决定。
- **遗留售后资金表不合并**：售后退款域既有的 `pending_financial_items` / `financial_records`（#63/#65 建立，售后单内部视图）保持为业务事实，由 #74 读取它们生成本模块的待确认事项，不做表名归并或数据迁移；两者职责不同（售后单内的退款记录 vs 全店资金事实），近形命名靠本条记录区分。
- #75 利润视图只读已确认口径；待确认事项单独列示，不进入利润。
- 便携版发布冒烟新增资金腿：待确认立账 → 部分确认两段到账 → 直接录入 → 重启读回，验证跨平台金额与历史一致。
- 发货记录、售后处理单、物流异常、供应方退货、采购订单与订单本身只作为来源被引用，不拥有资金字段。
