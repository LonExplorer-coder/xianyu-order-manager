# 闲鱼订单管理系统

一个面向个人卖家的本机订单管理工具：批量识别包含闲鱼订单详情的来源截图，将结果校对后汇总为可自定义表头的订单表、商品明细表和合并发货表。

当前状态：已进入第一阶段实施。应用已打通“批量选择 1–50 张闲鱼订单截图 → 本机队列持久化 → 后台逐张真实识别 → 确定性校验 → 自动入库或带原因校对 → 重复来源判断或新旧值确认更新 → 自定义业务字段 → 多套表格模板 → 默认脱敏的两表 Excel 导出 → 退出重启后继续”的纵向流程。Mac 与 Windows 免安装 ZIP 的构建和自动验证流程已经建立；合并发货和历史导入仍按后续 Issue 实施。

## 当前可运行能力

- 首次启动选择独立数据目录，之后自动打开最近目录。
- 空数据状态突出批量上传入口；已有订单时仍以订单表为主，并保留最近识别批次摘要。
- 有订单时首页显示在库订单、全部待确认和待发货数量；订单工作台支持全局搜索、买家与商品独立搜索、日期区间、平台、卖家账号、来源识别状态、平台交易状态、履约状态和生命周期状态的组合筛选与排序。
- 字段库可创建订单级或商品级的文本、数字、金额、日期时间、单选、多选和勾选字段；字段可设默认值与必填，默认值会明确应用到既有及后续记录。
- 自定义值与平台订单事实分开保存，可在新订单校对、订单更新校对和订单详情中填写。人工确认与详情保存会拦截最终状态中缺失的必填值；订单级必填字段没有默认值时，自动入库会转为人工确认。
- 订单工作台可切换“订单 / 商品”视图，并按对应粒度的自定义字段筛选与排序；多选字段按“包含全部所选项”筛选，勾选字段提供“未设置 / 是 / 否”三态，金额精确保存到分，日期时间固定按 Asia/Shanghai 显示。
- 可保存多套订单或商品明细表格模板，每套独立保存字段选择、表头别名、列顺序、筛选和排序；可使用商品总数量、订单总额和商品小计等受控计算字段，不提供任意公式入口。
- 应用模板时会原子恢复对应粒度、列与查询；可显式回到默认视图，删除正在使用的模板也会同步恢复默认结果，不会留下隐藏筛选。
- 可把当前筛选结果或勾选订单导出为同一个 Excel 文件中的“订单总表”和“商品明细”；两张表可分别选择对应粒度的模板，导出前显示订单数、商品明细数和脱敏摘要。
- 导出只在生成文件时默认遮盖收件人、手机号、详细地址和买家昵称，不修改系统内原始数据；订单号、交易号、手机号、金额和时间分别按适合 Excel 再处理的文本、数值与日期类型保存。
- 订单表直接展示平台与卖家账号、完整收件人/手机号/地址、多商品摘要和四个互不混用的状态维度；打开详情可继续核对完整订单、来源截图和历史变化。
- 单批可选择 1–50 张截图，51 张会被明确阻止；可连续创建多个批次，每张图独立显示等待识别、识别中、校验中、待确认、已入库、等待重试、失败、重复跳过或已取消。
- 选中的截图会先复制到数据目录的本机队列；离开批次页或退出应用都不会丢失未完成任务，重启后会从持久化状态继续处理。
- 断网或云服务暂时不可用时，单张截图按 30 秒、2 分钟、10 分钟、30 分钟、30 分钟受控退避，最多自动重试 5 次；同批其他截图不受阻塞。
- 等待重试或失败的单张任务可“立即重试”，也可“人工录入”生成空白校对草稿；两种操作都只影响目标截图，并保留来源图与最终来源快照。
- 把来源截图以 Base64 Data URL 直接发送到用户自己的中国北京百炼 `qwen3.5-ocr`，不依赖公共图床。
- 每张截图通常调用 2 次 OCR：第一次用完整图按文字坐标定位六个订单区域；本机随后裁掉订单详情下方的推广与底部操作区，第二次只从裁剪图提取前五区字段，底部履约按钮由第一次定位结果补回。不会追加第 3 次自动复核；裁剪失败、定位缺失、字段冲突或截图不完整时转入人工确认。
- 自动入库默认关闭；可在设置页立即开启或关闭。关闭时所有识别草稿先校对，开启后仅有完整、格式有效且无冲突的订单直接进入原始订单表。
- 自动入库不使用模型自报置信度；系统确定性校验订单号、收件人、手机号、完整地址、商品、金额、时间和商品明细合计。平台优惠可能使成交金额不等于商品总价加运费，因此不会把这种差额直接判为冲突；坐标定位失败、分区字段提取失败、区域证据冲突或截图不完整都会进入待确认。
- 批次页和校对页会显示结构化的待确认原因；这些原因随订单草稿保存，重启后仍可继续核对。
- 完全相同的图片会在付费 OCR 前按内容指纹跳过；内容指纹会在请求发出前持久保存，即使识别失败或应用重启，相同副本也不会重复发起付费调用，需从原失败项执行重试或人工录入。不同图片识别为同平台、同卖家账号、同订单号且内容等价时，只追加不可变来源，不创建第二笔订单。
- 同一订单的新截图若包含字段变化，无论自动入库是否开启都会保存为待确认来源；校对页明确展示当前值与新识别值，只有点击“确认更新订单”才会更新当前值。若 OCR 误把新订单命中已有订单，可直接修正卖家账号或订单号，系统会重新判断为新订单或切换到正确的已有订单。
- 每次确认更新都会校验订单版本并记录最小字段变化；过期校对会刷新当前版本并保留尚未提交的人工修正，不会覆盖较新的确认结果。订单详情可切换查看历次来源截图、对应修改版本和字段前后值。
- 识别订单号、支付宝交易号、买家与收货信息、地址、下单/付款时间、商品总价、运费、成交金额及一个或多个商品明细；通过页面位置约束区分买家昵称和收件人，并在模型漏拆时从完整地址补拆省、市、区县。
- OCR 未识别到的金额保留为空白并阻止确认；用户明确填写 `0.00` 才按零元保存。
- 识别 `×N`、`xN`、`数量 N`、`共 N 件` 等明确数量；截图未显示数量时默认记为 1，并在校对页直观提示“截图未显示数量，已按 1 件处理”。
- 对照来源截图校对规范化结果后确认入库；OCR 原始响应、规范化结果和最终值分开保留。
- 可取消本次校对：不会生成订单，且该草稿之后不能误入库；来源截图与识别证据仍保留以便追溯和后续容量清理。
- 订单、商品明细、来源截图及不可变来源快照保存在本机。
- 关闭并重开后继续查看原始订单；同一数据目录只允许一个写实例。
- 在设置页配置中国北京地域的百炼 `qwen3.5-ocr`，API Key 只保存到 macOS 钥匙串或 Windows 凭据管理器。
- 手动测试 OCR 连接；必须在费用提示中再次确认，默认测试和 CI 不发起付费调用。

## 本地开发

需要 Node.js 24.18.x 和 pnpm 10。项目根目录的 `.node-version` 已固定当前验证版本。

```bash
pnpm install
pnpm start
```

常用验证命令：

```bash
pnpm check
pnpm package
```

两平台免安装 ZIP 在对应系统上构建并验证：

```bash
# Apple 芯片 Mac
pnpm make:mac:portable
pnpm verify:portable

# 64 位 Windows
pnpm make:windows:portable
pnpm verify:portable
```

验证会从最终 ZIP 启动程序两次：首次选择独立数据目录并导入一单，删除第一份程序目录后，再从第二份程序读回原订单和来源截图；同时检查最终 ZIP 中的系统凭据库。日常 CI 会保留 ZIP、SHA-256 和机器可读验收证据 14 天。

macOS 普通本地打包会对整个应用执行临时签名，因此钥匙串功能可用；这个包仅适合本机或内部验证。正式对外分发使用 Apple Developer Program 的 `Developer ID Application` 证书，并把公证凭据保存在 macOS 钥匙串，而不是项目文件中：

```bash
xcrun notarytool store-credentials xianyu-order-manager-notary \
  --apple-id "你的 Apple ID" \
  --team-id "你的 Team ID"
pnpm make:mac:release
pnpm verify:mac:release
```

`notarytool` 会安全提示输入 Apple ID 的 App 专用密码。正式构建会自动启用 Hardened Runtime、Developer ID 签名和 Apple 公证；验证命令会检查签名、公证票据及 Gatekeeper。若要使用其他钥匙串配置名称，可通过 `XIANYU_NOTARY_KEYCHAIN_PROFILE` 指定。

Electron 只通过受限 preload 接口向界面开放目录选择、订单操作和不可读取原文的 OCR 凭据操作。结构化数据使用 Node 内置 SQLite，来源截图保存在所选数据目录的 `screenshots` 子目录；程序目录可以独立替换。

如需人工验证自己的百炼配置，请在“设置 → 百炼 OCR”中保存 Workspace ID 和 API Key，再点击“测试连接”。第二次确认后，应用会把一张程序内置的合成图片直接发送到百炼，这可能产生一次 OCR 调用；订单截图不会参与该连接测试。之后每张订单截图通常产生 2 次真实 OCR 调用：先用完整图定位平台状态、收货、商品、金额、订单详情和履约操作六区，再在本机裁掉推广与底部区域后，从裁剪图提取前五区字段；底部履约状态由第一次定位文字恢复，不会追加第 3 次自动复核。裁剪失败、定位缺失、区域证据冲突或截图不完整时，结果会保留并进入人工确认。

真实识别验收建议一次选择 2 张尚未入库、包含完整订单详情的截图：确认批次页会逐张更新且离开该页后仍继续处理，再分别核对订单号、交易号、买家昵称与收件人是否分离、手机号、省市区、三种金额、多商品条目数、明确数量和时间。修改任一字段并确认入库后，关闭并重开应用，订单详情应继续显示最终值和来源截图。

队列恢复验收可在正在识别或等待重试时退出应用，移动或删除原上传位置的文件后重开：历史批次应仍在，任务应使用数据目录内的队列副本继续。若服务持续失败，可确认“立即重试”仅重试该行；“人工录入”应打开带原图的空白校对页，填写后入库仍会产生不可变来源快照。取消流程可另上传一张合成或废弃截图验证：点击“取消本次校对”后应回到批次页，且不会新增订单。

自动入库验收可先保持默认关闭，上传一张完整截图并确认它进入待校对；再在“设置 → 自动入库”中开启开关，分别上传一张完整订单和一张缺少订单号或手机号的截图。前者应直接出现在订单表，后者应停在待确认并显示具体原因。关闭并重开应用后，开关状态和待确认原因应继续保留。

重复与更新验收可先确认一张订单，再重复上传完全相同的图片：批次结果应提示未再次调用 OCR。随后上传同一订单的另一张等价截图，应提示已记录新来源且订单表仍只有一笔。若新截图中的收件人、金额、状态或商品明细发生变化，校对页应显示当前值与新识别值；取消不会改变订单，确认后订单版本递增、详情保留两份来源，并可查看本次实际变化的字段。

订单工作台验收可准备多笔不同日期、买家、商品和状态的订单：确认首页三项数量准确、最近批次和上传入口可见；分别使用全局搜索、买家、商品、日期、平台/卖家和四种状态组合筛选，再切换金额或时间排序。表格应显示完整收件信息和多商品摘要，进入详情再返回后筛选条件仍保留；没有匹配结果时可直接清除筛选。

自定义字段验收可在“字段库”分别创建订单级文本字段和商品级勾选字段，设置默认值后确认既有订单与新订单均已获得该值；再创建一个无默认值的订单级必填字段，开启自动入库并上传新订单，确认它停在人工校对。补齐订单及每件商品的必填字段后入库，在详情修改并保存，重开应用确认值仍在；最后在订单、商品两个工作台分别执行自定义字段筛选和排序。可额外给已有订单上传一张内容变化截图，确认校对页会带出订单及匹配商品的原有自定义值，缺失的必填项可当场补齐，用户曾清空的值不会被默认值复活。

表格模板验收可先在订单工作台设置“待发货 + 金额倒序”，再在“表格模板”创建订单模板，选择内置字段、一个订单自定义字段和受控计算字段，修改表头并调整顺序后保存。应用后应同时恢复筛选、排序、列名与列顺序；切换“默认视图”应恢复默认结果。再创建一套商品明细模板，确认它不会混入订单级自定义字段，且即使未选“订单号”列仍可从操作列打开所属订单。关闭重开应用后两套模板都应保留。

Excel 导出验收可先筛选出数笔订单，直接点击“导出当前结果”；再勾选其中一笔，确认按钮和预览切换为“导出已选”。分别为订单总表和商品明细选择模板后保存，重新打开工作簿：订单总表应一单一行，商品明细应一条商品明细一行；收件人只保留姓氏、手机号只保留前 3 后 4 位、地址只保留省市区、买家昵称只保留首尾字符。系统订单详情仍应显示完整原始信息。

## 隐私说明

上传订单截图后，图片会发送到用户所配置的阿里云百炼服务进行两阶段识别：第一次发送完整图获取文字坐标；布局有效时，本机物理裁掉订单详情下方的推广与底部操作区，第二次只发送裁剪图提取前五区字段，底部履约信号由第一次结果恢复。正常流程最多发送 2 次，不追加第 3 次自动复核；裁剪失败会回退完整图并要求人工确认。单张原文件上限为 7.5 MB，网络请求禁止自动重定向。原图、结构化订单和不可修改的识别证据同时保存在用户选择的本机数据目录。API Key 仅由系统凭据库保存，不进入订单数据库、日志、识别证据、备份或导出；若上游异常回显实际密钥，应用会拒绝保存该响应。真实来源截图、API Key、本机数据库和备份不得提交到代码仓库；自动化测试只使用程序生成的脱敏合成图片与固定服务端响应，不发起付费调用。
